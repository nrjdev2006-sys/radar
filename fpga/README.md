# FPGA timing core

## Current block

`rtl/radar_pulse_timing.v` is a synthesizable, board-independent PL pulse sequencer. It creates a local-clock `tx_gate`; it does not send Ethernet packets, configure an RF transceiver, drive an antenna directly, or capture ADC samples.

`rtl/radar_axi_pulse.v` wraps the pulse sequencer in a 32-bit AXI4-Lite register peripheral. The current register map is:

| Offset | Access | Meaning |
|---|---|---|
| `0x00` | Write | Control: bit 0 sends start; bit 1 sends stop (stop takes priority if both are written) |
| `0x04` | Read/write | Pulse width in PL clock ticks |
| `0x08` | Read/write | PRI in PL clock ticks |
| `0x0C` | Read | Status: bit 0 busy, bit 1 configuration error, bit 2 TX gate |
| `0x10` | Read | 32-bit pulse-start count; wraps naturally |

Unmapped reads and invalid writes return AXI `SLVERR`. The AXI and timing core use one clock in this first version, so the wrapper does not yet cross clock domains.

## PS driver

`ps/radar_driver.c` is a bare-metal Cortex-A9 driver. The board-specific application supplies the base address generated by Vivado; no address is guessed here. `ps/radar_demo.c` shows how to configure and stop an eight-pulse burst. Its `0x40000000` base in the compile script is a syntax-check placeholder, not a board address.

Compile with the installed Xilinx SDK compiler:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\fpga\ps\build_driver.ps1
```

## Simulation and synthesis

All timing values are **clock ticks** in the `clk` domain:

- `cfg_pw_ticks` must be at least 1.
- `cfg_pri_ticks` must be greater than `cfg_pw_ticks`.
- A one-clock `start` while idle latches the settings and begins a pulse on the accepting clock edge.
- Subsequent leading edges are separated by exactly `cfg_pri_ticks` clocks.
- `tx_gate` remains high for exactly `cfg_pw_ticks` clocks.
- A one-clock `stop` ends the train. A start while busy is ignored.
- `config_error` stays high after an invalid start until a valid start or reset.
- `pulse_start` is a one-clock marker at every pulse leading edge.
- `rst_n` is an active-low synchronous reset.

The PS must validate that register writes are in range and synchronize control/configuration into this clock domain safely. The board clock frequency converts ticks to time (`seconds = ticks / clock_hz`). The clock frequency, AXI/PS wrapper, reset wiring, and RF gate connection are deliberately not guessed until the board is identified.

## Simulation

With the installed Vivado 2014.4 simulator, run from the project root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\fpga\sim\run_xsim.ps1
```

The self-checking testbench verifies 3-clock pulse width, 8-clock PRI, start markers, stop behavior, and rejection of `PW >= PRI`. It is a functional timing simulation, not a board programming or RF test.

The AXI testbench exercises independent AW/W channel acceptance, register readback, status, pulse counting, start/stop, and an unmapped-read SLVERR. Run both testbenches with the same simulation command above.

The standalone PL peripheral synthesizes with the installed Vivado 2014.4 tools using a representative Zynq-7020 part:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\fpga\synth\run_synth.ps1
```

Pass another part using `-Part <part>`. The default `xc7z020clg400-1` is provisional, because the physical board has not been identified. The report and synthesized checkpoint are copied to `fpga/build/provisional_zynq7020/`. This synth run covers the PL peripheral only, not the PS7 hard block or a board-specific bitstream.

## Provisional PS7 + PL system

The Vivado 2014.4 IP Integrator script builds a complete provisional Zynq system: PS7 `M_AXI_GP0` → AXI interconnect → this PL peripheral; PS7 `FCLK_CLK0` is set to 100 MHz; Vivado automation supplies the reset path; and `tx_gate`, `DDR`, and `FIXED_IO` are exposed at the wrapper. The generated address map assigns the peripheral a 64 KiB segment at `0x43C00000` for this provisional design.

Build and synthesize it with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\fpga\bd\run_system_build.ps1
```

The block design, wrapper, system utilization report, and synthesized checkpoint are saved under `fpga/build/provisional_zynq7020_pspl/`. This design has not been simulated through the PS processor because the Vivado Zynq BFM reports that an AXI BFM license is required. The AXI peripheral has its own self-checking bus simulation, and the PS C driver is compiled separately.

The PS7 was built without a board preset. Its DDR/MIO settings, package pins, clock constraints, and `tx_gate` destination must be set for the actual board before implementation or programming. This provisional synthesis must not be treated as a board-ready bitstream.

## Current Vivado 2024.2 project and Vitis PS source

Open the generated Vivado project at `fpga/vivado/radar_vivado_project/radar_vivado.xpr`. Its block design is `radar_system.bd`; the exported XSA is `radar_hardware.xsa`. Regenerate it with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\fpga\vivado\build_project.ps1
```

The Tcl builder applies the Digilent Zybo Z7-10 preset (`xc7z010clg400-1`), enables PS GEM0 RGMII on MIO 16–27 and MDIO/MDC on MIO 52–53, constrains `tx_gate` to user LED 0 (M14, LVCMOS33), then synthesizes, implements, generates a bitstream, and exports a fixed XSA. AMD describes the fixed-XSA-to-platform-component workflow in [UG1400](https://docs.amd.com/r/2024.2-English/ug1400-vitis-embedded/Creating-a-Platform-Component-from-XSA?contentId=MdSq5zyL4vJ2fbnb_oUrVA).

The PS application entry point is `fpga/vitis/app_src/main.c`; the shared driver is `fpga/ps/radar_driver.c` and `.h`. The Vitis 2024.2 creation script is `fpga/vitis/create_vitis_workspace.py`, run with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\fpga\vitis\build_vitis.ps1
```

**Vitis status:** Vivado project, routed design, bitstream, and XSA complete successfully. Vitis Unified 2024.2 stops during SDT generation (`Error in generating SDT for given XSA`); no platform or application build is claimed. XSCT reads the XSA but cannot complete because the installed Unified package lacks the classic IDE service and registered `zynq_fsbl` template.

**Bitstream status:** the board-preset build generates a routed bitstream. `tx_gate` drives the user LED for visible pulse timing; this is not an RF radar output.
